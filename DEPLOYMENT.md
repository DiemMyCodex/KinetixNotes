## 2. Bước 1: Cập Nhật Supabase Schema & Row-Level Security (RLS)

Hệ thống bảo mật của KinetixNotes áp dụng nguyên tắc **Zero Trust** thông qua Postgres Row-Level Security (RLS):
- Bảng `public.lessons`: Cho phép mọi người (khách chưa đăng nhập lẫn người dùng đã đăng nhập) được đọc (`SELECT`). Tuyệt đối chỉ cho phép người dùng có email `diemmycodex@gmail.com` được ghi (`INSERT`), sửa (`UPDATE`) và xóa (`DELETE`).
- Bảng `public.user_progress`: Mỗi người dùng chỉ được đọc, tạo hoặc xóa bản ghi tiến độ (`lesson_id`) của chính tài khoản mình (`auth.uid() = user_id`).

### Quy trình thực hiện trên Supabase Dashboard:

1. Đăng nhập vào trang quản trị Supabase:
   👉 **URL**: [https://supabase.com/dashboard/project/fsrdqmraatuzhdzdbfrk/sql/new](https://supabase.com/dashboard/project/fsrdqmraatuzhdzdbfrk/sql/new)
2. Chọn menu **SQL Editor** ở thanh điều hướng bên trái.
3. Bấm **+ New query** (Tạo câu truy vấn mới).
4. Sao chép và dán toàn bộ đoạn mã SQL chuẩn dưới đây (nội dung từ `supabase/schema.sql`):

```sql
-- ==============================================================================
-- KinetixNotes Supabase Schema & Row Level Security (RLS)
-- Mục tiêu: Cấp quyền SELECT công khai cho lessons, chỉ diemmycodex@gmail.com được ghi/sửa/xóa,
--           và bảo vệ tiến độ học tập user_progress riêng tư theo auth.uid().
-- ==============================================================================

-- 1. Tạo bảng bài học (lessons)
create table if not exists public.lessons (
  id bigint generated by default as identity primary key,
  user_id uuid references auth.users (id) on delete set null,
  category text not null check (category in ('Máy tính', 'Trí tuệ AI', 'Tâm lý & Sống', 'Kinh tế')),
  title text not null,
  summary text not null,
  points jsonb not null default '[]'::jsonb,
  quiz text not null,
  answer text not null,
  created_at timestamptz not null default now()
);

-- Kích hoạt RLS cho bảng lessons
alter table public.lessons enable row level security;

-- 1.1 Policy SELECT: Mọi người đều được đọc danh mục bài học
drop policy if exists "Anyone can read lessons" on public.lessons;
create policy "Anyone can read lessons"
  on public.lessons
  for select
  using (true);

-- 1.2 Policy INSERT: Chỉ admin diemmycodex@gmail.com được tạo bài học mới
drop policy if exists "Authenticated users can insert their own lessons" on public.lessons;
drop policy if exists "Only admin can insert lessons" on public.lessons;
create policy "Only admin can insert lessons"
  on public.lessons
  for insert
  to authenticated
  with check (
    auth.uid() = user_id
    and lower(coalesce(auth.jwt() ->> 'email', '')) = 'diemmycodex@gmail.com'
  );

-- 1.3 Policy UPDATE: Chỉ admin diemmycodex@gmail.com được sửa bài học
drop policy if exists "Users can update their own lessons" on public.lessons;
drop policy if exists "Only admin can update lessons" on public.lessons;
create policy "Only admin can update lessons"
  on public.lessons
  for update
  to authenticated
  using (
    auth.uid() = user_id
    and lower(coalesce(auth.jwt() ->> 'email', '')) = 'diemmycodex@gmail.com'
  );

-- 1.4 Policy DELETE: Chỉ admin diemmycodex@gmail.com được xóa bài học
drop policy if exists "Users can delete their own lessons" on public.lessons;
drop policy if exists "Only admin can delete lessons" on public.lessons;
create policy "Only admin can delete lessons"
  on public.lessons
  for delete
  to authenticated
  using (
    auth.uid() = user_id
    and lower(coalesce(auth.jwt() ->> 'email', '')) = 'diemmycodex@gmail.com'
  );

-- 2. Tạo bảng tiến độ người dùng (user_progress)
create table if not exists public.user_progress (
  user_id uuid not null references auth.users (id) on delete cascade,
  lesson_id bigint not null,
  created_at timestamptz not null default now(),
  primary key (user_id, lesson_id)
);

-- Kích hoạt RLS cho bảng user_progress
alter table public.user_progress enable row level security;

-- 2.1 Policy SELECT tiến độ: User chỉ đọc được tiến độ của chính mình
drop policy if exists "Users can view their own progress" on public.user_progress;
create policy "Users can view their own progress"
  on public.user_progress
  for select
  to authenticated
  using (auth.uid() = user_id);

-- 2.2 Policy INSERT tiến độ: User chỉ đánh dấu hoàn thành cho chính mình
drop policy if exists "Users can insert their own progress" on public.user_progress;
create policy "Users can insert their own progress"
  on public.user_progress
  for insert
  to authenticated
  with check (auth.uid() = user_id);

-- 2.3 Policy DELETE tiến độ: User chỉ bỏ đánh dấu cho chính mình
drop policy if exists "Users can delete their own progress" on public.user_progress;
create policy "Users can delete their own progress"
  on public.user_progress
  for delete
  to authenticated
  using (auth.uid() = user_id);
```

5. Nhấn nút **Run** (hoặc tổ hợp phím `Ctrl + Enter` / `Cmd + Enter`).
6. **Xác nhận kết quả thực thi**:
   - Thông báo hiển thị: `Success. No rows returned`.
   - Vào menu **Database** -> **Tables**: Kiểm tra 2 bảng `lessons` và `user_progress` đã có biểu tượng ổ khóa màu xanh (RLS enabled).
   - Vào menu **Database** -> **Policies**:
     * Bảng `lessons`: Có 4 policies (`Anyone can read lessons`, `Only admin can insert lessons`, `Only admin can update lessons`, `Only admin can delete lessons`).
     * Bảng `user_progress`: Có 3 policies (`Users can view their own progress`, `Users can insert their own progress`, `Users can delete their own progress`).

## 4. Bước 3: Triển Khai Lên Vercel & Thiết Lập Biến Môi Trường

### Cấu hình dự án trên Vercel:
- **Framework Preset**: `Vite`
- **Build Command**: `npm run build`
- **Output Directory**: `dist`
- **Install Command**: `npm install`
- **SPA Rewrites**: Đã được định nghĩa sẵn trong `vercel.json`:
  ```json
  {
    "rewrites": [{ "source": "/(.*)", "destination": "/index.html" }]
  }
  ```

### Thiết lập biến môi trường (Environment Variables):
Vite yêu cầu các biến môi trường phía client bắt buộc phải có tiền tố `VITE_` để được bundle vào file tĩnh khi build:

1. Mở **Vercel Dashboard** -> Chọn project KinetixNotes.
2. Điều hướng tới **Settings** -> **Environment Variables**.
3. Thêm 2 biến sau (tích chọn cả 3 môi trường: `Production`, `Preview`, `Development`):

| Tên biến (Key) | Giá trị (Value) | Mô tả |
| :--- | :--- | :--- |
| `VITE_SUPABASE_URL` | `https://fsrdqmraatuzhdzdbfrk.supabase.co` | URL kết nối Supabase project |
| `VITE_SUPABASE_ANON_KEY` | `sb_publishable_SxgPR39Zr1OPdNOC80yXRg_yOVSXyaS` | Publishable/Anon API key |

4. **Kích hoạt Build lại (Redeploy)**:
   - Sau khi lưu biến môi trường, vào tab **Deployments**.
   - Bấm vào nút `...` của bản build gần nhất -> Chọn **Redeploy**.
   - Lý do: Vite nhúng giá trị biến môi trường trực tiếp vào mã JS khi chạy lệnh `npm run build`; nếu không redeploy, bản build cũ sẽ không nhận biến mới.

## 5. Bước 4: Đồng Bộ Supabase Site URL & Redirect URLs

Để các tính năng đăng nhập, đăng xuất, lưu phiên session và làm mới token (OAuth/Magic Link/Email Confirmation) không bị lỗi chuyển hướng hoặc lỗi chặn nguồn (CORS/Redirect mismatch), bạn cần khai báo domain Vercel vào Supabase.

1. Lấy tên miền Vercel thực tế sau khi deploy (Ví dụ: `https://kinetix-notes.vercel.app` hoặc domain riêng nếu có).
2. Vào Supabase Dashboard:
   👉 **URL**: [https://supabase.com/dashboard/project/fsrdqmraatuzhdzdbfrk/auth/url-configuration](https://supabase.com/dashboard/project/fsrdqmraatuzhdzdbfrk/auth/url-configuration)
3. Điền các mục như sau:
   - **Site URL**: Điền URL chính thức của ứng dụng trên Vercel:
     ```text
     https://kinetix-notes.vercel.app
     ```
   - **Redirect URLs**: Bấm **Add URL** để bổ sung các mẫu chuyển hướng (hỗ trợ cả môi trường dev local và wildcard production):
     * `https://kinetix-notes.vercel.app/**`
     * `http://localhost:3000/**`
     * `http://localhost:5173/**`
4. Bấm **Save** để lưu cấu hình.

## 7. Xử Lý Sự Cố Thường Gặp (Troubleshooting)

Đăng xuất và đăng nhập lại trên web để nhận JWT token mới. |
| **Màn hình trắng hoặc không kết nối được Supabase trên Vercel** | Chưa cấu hình hoặc cấu hình sai biến môi trường `VITE_SUPABASE_*` | Kiểm tra lại mục Environment Variables trên Vercel, đảm bảo biến có tiền tố `VITE_` và thực hiện **Redeploy**. |

| **Deep link `/bai/:id` trả về trang chủ** | Rewrite trong `vercel.json` bị thay đổi | Giữ `rewrites` về `/(.*)` → `/index.html`; không chặn nhầm `assets/`, `sw.js`, `manifest.webmanifest`. |
